# Contributing

The protocol is experimental. Small, reviewed changes with explicit compatibility
consequences are preferred. Keep Exim behavior, queue execution, transport loops,
HTTP, persistence, metrics, and UI out of this repository.

## Development environment

Linux amd64 is the initial CI target. The wire contract is architecture independent.
The C protocol codec targets C11 with GCC or Clang. The Go codec uses Go 1.27.x
and the standard library; it does not contain agent logic.
Observer implementations in other languages belong in separate repositories.

Required tools:

| Tool                         | Policy                                                     |
| ---------------------------- | ---------------------------------------------------------- |
| GCC / Clang                  | CI Ubuntu 24.04 GCC and Clang 18; C11 warnings in Makefile |
| clang-format                 | exactly 18.1.8 from tools/requirements.txt                 |
| clang-tidy                   | CI 18; local newer versions may add diagnostics            |
| cppcheck                     | CI distro version (2.13+); local 2.20 also checked         |
| Python                       | 3.10+ with PyYAML 6.0.3                                    |
| Node.js / npm                | Node 22+; CI 24                                            |
| Prettier / markdownlint-cli2 | package-lock.json pins 3.9.9 / 0.23.3                      |
| yamllint                     | 1.35+; CI distro version                                   |

Install system compilers, clang-tidy, cppcheck, Python venv support, yamllint,
Node and npm using your operating system package manager. Then explicitly run:

```sh
./scripts/setup-dev.sh
make tools-check
make tools-go
```

This opt-in script uses the network to install pinned formatters
under ignored `.tools/` and npm tools under `node_modules/`. `make` never installs
or downloads tools. Make prepends `.tools/venv/bin` and `.tools/bin`
to PATH. Existing compatible system tools also work. Normal tests have no external
API, network, local clock, host name, or random-order dependency.

## Local workflow

```sh
make fmt
make generate
make check
make test-sanitize CC=clang
make fuzz-smoke
```

`make fmt` writes C, YAML, JSON, and Markdown formatting. `make fmt-check` is
read-only and fails on any difference. Generated artifacts are checked in temporary
files, including before they are tracked by Git. Golden binaries are never
regenerated by these commands. `make test`, `make test-c`,
`make test-vectors`, and `make test-compat` are offline after setup. Sanitizers
and fuzz targets are separate because their toolchain requirements differ.

`make check` covers format, spec, generated files, clang-tidy, cppcheck,
YAML/Markdown lint, unit/round-trip/golden tests, and
negotiation compatibility. CI additionally uses both C compilers with `-Werror`,
sanitizers, fuzz smoke, and CodeQL. Local baseline warnings are strong
but only implicit declarations are universally fatal; additional warnings become
fatal in the controlled CI compiler jobs.

## Analysis choices

clang-tidy enables analyzer, bugprone, performance, portability, CERT numeric
conversion, and misleading-indentation checks. Deliberately disabled:

- Easily-swappable parameters: the public pointer/length codec API is intentional.
- Unsafe-functions / DeprecatedOrUnsafeBufferHandling: bounded memcpy/memset are
  intentional; optional C Annex K alternatives are not portable dependencies.
- Not-null-terminated-result: binary wire buffers must not gain NUL terminators.

cppcheck suppresses missing system headers only; it retains warning/style/performance/
portability findings. Failures are not swallowed. Formatter and linter exceptions
need a reason alongside their use.

## Protocol change process

Before editing bytes, document the problem, compatible migration, allocation bounds,
unknown-data behavior, and numeric allocation. Add an ADR when changing foundations.
Update spec, documentation, and the C implementation together. Add a semantic golden pair, negative
cases, round trips, and compatibility evidence. Generate constants with
`make generate`; never hand-edit generated files. Keep stable vectors immutable.

The explicit initial draft recipe is `python3 tools/create-vectors.py`; review the
binary diff and semantic companions before accepting changes. Add new versioned
recipes/fixtures for stable evolution. Shared tests must verify both encode and
decode against expectations independent of the codec. Changes to a supported
message are incomplete without corresponding corpus updates.

Open a pull request using the checklist. Update CHANGELOG.md, highlighting wire
breaks separately from helper API changes. Do not include private mail data.

## Dependencies and releases

C uses the standard library and has no external runtime dependencies. Dev-only Python and npm tools have specific generation/formatting roles.
A new dependency needs a safety or maintenance justification and reproducibility review.

The release workflow verifies the repository and uploads a source archive and
SHA-256 checksum for maintainer review. It does not publish a GitHub release or
claim protocol stability automatically. Stabilization and public release notes
require an explicit maintainer decision. Enable private vulnerability reporting
and branch protection when configuring the GitHub repository.

Go development requires Go 1.27.x. Run `make test-go lint-go fuzz-go`;
`make check` includes Go race tests, vet, formatting and shared golden vectors.
All wire changes must update both codecs and shared fixtures together.

## Go analysis (adapted from fsledger)

Install explicitly with `make tools-go` (network access). Versions are pinned in
`scripts/go-analysis.mk`: golangci-lint v2.13.2, govulncheck v1.7.0 and NilAway
v0.0.0-20260802165852-32ec3a0e8a41, matching fsledger. Local analysis was verified
with Go 1.27.1. Modules require Go 1.27.0 and CI selects the 1.27.x series.
Binaries live in ignored `.tools/bin`; ordinary builds never install tools.

- `make lint-go`: verify versions/configuration and run golangci-lint, including
  govet, Staticcheck, errcheck, gosec, dependency restrictions and correctness checks.
- `make nilaway`: check potential nil dereferences, including normal test files.
- `make fmt`: apply gofumpt, goimports and golines (120-column limit) to Go.
- `make check`: offline analysis plus formatting and tests.
- `make vuln`: explicit online vulnerability audit including tests; also runs in CI.
  It is separate from offline checks and does not suppress findings or network failures.

The configuration reuses fsledger's tool versions, strict error checks, generated
file handling and formatters. It deliberately selects correctness/security linters
instead of its all-linter style policy. The import allowlist matches this repository;
fsledger's application dependencies and DTO exceptions are not copied. Govet's
fieldalignment suggestion is disabled to preserve deliberate API field ordering.
Narrow inline suppressions require a named linter and a reason: bounded conversions,
repository-only fixture paths, private directory permissions and best-effort cleanup
are documented at their call sites. Generated registries retain generator formatting.

## Go 1.27 workflow

The go.mod minimum is 1.27.0; the agent workspace uses the same minimum. CI
selects Go 1.27.x, allowing patch upgrades within that series. Locally the normal
commands default to GOTOOLCHAIN=local so an old compiler fails explicitly rather
than downloading another toolchain during an offline build.

`make fix-go` runs the installed Go modernizers and then the pinned formatters.
`make fix-go-check` runs `go fix -diff` without changing files; it is included in
`make check`. The agent also checks integration-tagged test code. Inspect available
modernizers with `go tool fix help`. The revamped command was introduced in
[Go 1.26](https://go.dev/doc/go1.26#tools) and is available in the installed 1.27.x
toolchain; these are not all features first introduced in 1.27.

Tool installation stays separate from the runtime module: `make tools-go` installs
pinned development binaries, preserving dependency-free protocol/runtime packages.
